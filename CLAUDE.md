# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**SRT TTS Studio** — Windows desktop app (CustomTkinter) that converts SRT subtitle files and PDFs to TTS audio (MP3) via Microsoft Edge TTS and Vietnamese TTS APIs (FPT.AI, Vbee, Zalo AI, EverAI, MiniMax). Also includes RVC voice cloning, VoxCPM voice cloning, VieNeu-TTS voice cloning, F5-TTS-Vietnamese voice cloning, OmniVoice Vietnamese voice cloning, Video OCR, Speech-to-Text, video compression, audio→video muxing, and video repair utilities. Distributed as `.msi` installer and standalone `.exe` files via PyInstaller + WiX Toolset.

## Build Commands

```bat
:: Full build — all 4 outputs (recommended)
build_all.bat

:: MSI-only rebuild (skips onefile exes, faster for WiX iteration)
build_msi_protected.bat

:: Dev run (no build needed)
python apppp_integrated.py

:: Pre-build sanity: catch Cython compile errors WITHOUT a full 10-min build
python -m py_compile apppp_integrated.py   :: fast, but LESS strict than Cython
python -c "from Cython.Build import cythonize; cythonize('apppp_integrated.py', compiler_directives={'language_level':'3'}, build_dir='cython_build_test', quiet=True); print('CYTHON OK')"
:: then clean: cython_build_test\ + apppp_integrated.c

:: Post-build audit (these scripts live in repo root)
python _verify_security.py   :: PYZ has only the .pyd, no .pyc; onedir .pyd present; .integrity matches exe
python _audit_deps.py        :: every external env/model/cache resolvable on THIS machine

:: Regenerate integrity manifest after modifying onedir dist
python gen_integrity.py

:: Regenerate secured-exe companion integrity
python gen_self_hash.py "dist\SRT_TTS_Studio_Secured.exe"

:: Source-only backup zip (no models/envs/artifacts/secrets) → E:\SRT_TTS_Studio_source_<stamp>.zip
powershell -ExecutionPolicy Bypass -File make_source_zip.ps1
```

**Manual testing**: there is no automated test suite. `TEST_CHECKLIST.md` (repo root, Vietnamese) is the manual smoke-test checklist for recently added features — run through the relevant section after touching a feature area, and add checklist items when adding new features.

**To invoke `build_all.bat` from a script/automation** (git-bash converts `/c` to `C:/` — use this form):
```bash
MSYS_NO_PATHCONV=1 cmd.exe /c "E:\path\to\run_build.bat"
# where run_build.bat contains: cd /d <project_dir> && call "<abs_path>\build_all.bat"
```
Note: background shell processes do not inherit cwd — always use absolute path in `call`.

**Build interpreter:** the app is built with **Python 3.14** (system `C:\Python314\python.exe`), so Cython emits `apppp_integrated.cp314-win_amd64.pyd` and PyInstaller embeds a matching 3.14 runtime. The `.pyd` ABI tag (`cp314`) must match the bundled Python — if you rebuild with a different Python, the integrity hash, the embedded interpreter, and the `.pyd` all change together. This is **independent** of the companion-script venvs, which are separate external Pythons (`rvc_env`=3.10, `voxcpm_env`=3.11, `f5tts_env`/`omnivoice_env`=3.10, etc.) invoked as subprocesses.

**Verifying the build / security after `build_all.bat`** (the standalone onefile exes are what gets distributed, so check those — not just onedir):
```python
from PyInstaller.archive.readers import CArchiveReader
for exe in ("output/Portable/SRT_TTS_Studio_Portable.exe",
            "output/Portable/SRT_TTS_Studio_Secured.exe",
            "output/Portable/SRT_TTS_Studio_Trial.exe"):
    names = list(CArchiveReader(exe).toc.keys())
    hits = [n for n in names if "apppp_integrated" in n]
    assert hits == ["apppp_integrated.cp314-win_amd64.pyd"], (exe, hits)  # ONLY the .pyd, no .pyc
```
Two repo-root helper scripts automate the post-build checks (re-run after every build): **`_verify_security.py`** verifies all 3 onefile exes (only `.pyd` in the CArchive, no `.pyc`) AND the onedir build (`.pyd` is a **loose file** in `dist\SRT_TTS_Studio\_internal\`, NOT in a CArchive — so it's checked by file presence + "no leaked `apppp_integrated*.pyc`", not via `CArchiveReader`), plus that `SRT_TTS_Studio_Secured.exe.integrity` matches the freshly-built exe's SHA-256. **`_audit_deps.py`** confirms every external dependency is resolvable *the way the app resolves it* (e.g. `voxcpm_env` is found by walking up from the VoxCPM model dir, not just beside the exe) and reports what `output\Portable\` still needs hand-copying for another machine. **`_strings_audit.py`** is a manual forensic check — it scans the built `.pyd` (`dist\SRT_TTS_Studio\_internal\apppp_integrated.cp314-win_amd64.pyd`) for leaked ASCII runs (function names, the source filename, secret-like literals) to confirm Cython left nothing recoverable; run it ad-hoc after a build when auditing protection.

**Cython is stricter than CPython — `py_compile` passing does NOT mean the build will compile.** The one that bites: a guarded reference to a never-assigned module global, e.g. `_OK if '_OK' in globals() else default`, is valid Python (the guard is runtime) but Cython rejects it at **compile time** with `undeclared name not builtin: _OK` and aborts step 5. Use `globals().get("_OK", default)` instead (never names the symbol). (`'__file__' in globals()` is fine — Cython knows `__file__`.) Always run the `cythonize(...)` one-liner above before kicking off a 10-minute `build_all.bat`.

## Build Pipeline (build_all.bat, steps 0–9)

| Step | What happens |
|---|---|
| 0 | Source validation — aborts if any companion `.py`, model `.pt`, `rvc_env\Scripts\python.exe`, spec, `.dat`, or `srt_tts_launch.py` is missing |
| 1–3 | Python deps, MSVC Build Tools, WiX Toolset v3 (auto-install if absent) |
| 4 | **PyArmor DISABLED** — was inert (runtime never reached bundle); Cython is the real protection layer |
| 5 | Cython compiles `apppp_integrated.py` → `cython_out\apppp_integrated.cp3xx-win_amd64.pyd` (native DLL). The `.pyd` goes to `cython_out\` (off pathex) so PyInstaller's dep-tracing still reads the `.py` source. |
| 6A | PyInstaller onedir using `SRT_TTS_Studio_onedir.spec` |
| 6B | Bundle ffmpeg/ffprobe |
| 6C | `gen_integrity.py` |
| **6G** | **FAIL-CLOSED** copy of 15 companion `.py` + `hubert_base.pt` + `rmvpe.pt` + `rvc_env\` into `dist\SRT_TTS_Studio\`; verifies each file landed; aborts if anything missing. Must run before step 7 so WiX Heat picks them up. |
| 6D/E/F | 3 onefile PyInstaller builds (Portable / Secured / Trial) |
| 9 (Portable pack) | Copies onefile exes + 15 companion `.py` + `hubert_base.pt` + `rmvpe.pt` + `rvc_env\` + **`F5-TTS-Vietnamese-ViVoice\` (F5 model, ~5.4 GB, robocopy if `model_last.pt` present)** into `output\Portable\`. The F5 model is the one large model the build copies — all other big envs/models are hand-copied (see output layout below). |
| 7–8 | WiX Heat → candle → light → MSI (source: `product.wxs`). Step 7 first `del`s any stray `auth.dat`/`.lockout` from `dist\` (never package a build-machine credential). Step 8 reads `VERSION.txt` (repo root, default `1.0.0`) into `%APP_VERSION%` and passes it as `candle -dProductVersion=%APP_VERSION%`. |
| 9 | `output\SRT_TTS_Studio_Setup.msi` + `output\Portable\` (exes + companion files + models + rvc_env) |

**MSI versioning / update-without-uninstall**: `product.wxs` takes `Version="$(var.ProductVersion)"` (default `1.0.0` via `<?ifndef?>`) and uses `<MajorUpgrade AllowSameVersionUpgrades="yes" …>`. To ship an update: **bump `VERSION.txt`** (e.g. `1.0.0` → `1.0.1`) and rebuild — users just run the new `.msi` and it auto-removes the old + installs the new in one step (no manual uninstall). Windows Installer ignores the 4th version field, so bump one of the first 3. **Never change `UpgradeCode`** in `product.wxs` (`A1B2C3D4-…`) — it's what links versions as upgrades of the same product.

## Critical: Security / Code Protection Architecture

**The entry point is `srt_tts_launch.py`, not `apppp_integrated.py`.**

```python
# srt_tts_launch.py — entire content:
import apppp_integrated  # executes the whole app (mainloop is at module level)
```

All 4 specs use `srt_tts_launch.py` as entry and include this critical filter:

```python
# Strip the plaintext bytecode of the main module from the PYZ —
# ship ONLY the one-way-compiled .pyd (native machine code).
a.pure = [x for x in a.pure
          if not (x[0] == 'apppp_integrated' or x[0].startswith('apppp_integrated.'))]
```

**Without this filter**: PyInstaller embeds `apppp_integrated.py` as recoverable bytecode (1 MB marshal blob). An attacker extracts all function names + `_HMAC_SECRET`/`_PBKDF2_SALT` byte literals in ~2 minutes via `pyinstxtractor` + `marshal.loads`. With the filter: only the PE DLL (`.pyd`) is in the archive; `marshal.loads` rejects it and no Python decompiler exists for Cython output.

**Cython string storage note**: Python string literals compiled by Cython are stored as `PyObject*` intern references in the `.pyd`, NOT as flat raw bytes. Searching the `.pyd` binary for string content will return no matches — this is correct and expected.

**Verifying the protection is working** (run after any build):
```python
from PyInstaller.archive.readers import CArchiveReader
import marshal
r = CArchiveReader("dist/SRT_TTS_Studio/SRT_TTS_Studio.exe")
names = list(r.toc.keys())
# Must be EMPTY — if 'apppp_integrated' appears as bytecode, the strip filter was lost
assert not any('apppp_integrated' in n for n in names if not n.endswith('.pyd'))
```

### Security layers at runtime
1. **Cython `.pyd`** — native x64 machine code; no Python decompiler exists
2. **Integrity check** (`_check_integrity`, line ~115) — SHA-256 of `.exe` + `.pyd` vs `.integrity` file; fail-closed; runs at import time before any UI
3. **Self-integrity** (Secured variant only) — SHA-256 + HMAC of exe vs companion `.integrity`
4. **Hardware DRM** — `auth.dat` HMAC-signed with CPU `ProcessorId` + C: volume serial. **`PASSWORD_FILE`/`LOCKOUT_FILE` are `os.path.join(_CONFIG_DIR, ...)`**, NOT CWD-relative — under an MSI install the CWD is read-only `C:\Program Files\…`, so a relative path would `PermissionError` on set-password and "lose" the login when CWD changes. Both files are in the `_migrate_config_from_exe_dir()` copy list so a portable→installed move carries the existing credential over. Both build scripts `del` any stray `auth.dat`/`.lockout` from `dist\SRT_TTS_Studio\` **before** WiX Heat harvest (step 7), so a build-machine credential is never packaged into the MSI.
5. **PBKDF2 password** — 200k iterations; `_HMAC_SECRET` / `_PBKDF2_SALT` XOR-split across two byte literals in source (do NOT change after deployment — breaks existing `auth.dat`)
6. **Brute-force lockout** — 5 failures → 15-min lockout in `.lockout` file (HMAC-signed, hardware-bound)
7. **Trial** (Trial variant only) — 24h via registry×2 + `%LOCALAPPDATA%` file; anti-rollback; `_detect_vm()` blocks trial in VMs/sandboxes

Security checks run at **module import time** (top-level, before `if __name__`): `_check_integrity()` → `_check_self_integrity()` → `_check_trial()`.

### VM Detection (`_detect_vm`) Architecture

`_detect_vm()` is called only from `_check_trial()` and only when `build_type_trial.dat` is present in `sys._MEIPASS` (i.e., only the Trial variant blocks VMs). Non-trial builds skip it entirely.

Detection uses 6 independent layers — passing one layer is enough:

| Layer | Method | Covers |
|---|---|---|
| 0 | `USERNAME == WDAGUtilityAccount` env var + `WDAGAgent.exe` process | Windows Sandbox (100% definitive) |
| 1 | Registry keys: `vmicheartbeat`, `vmicshutdown`, `vmicvss`, `vmicrdv` services; `Virtual Machine\Guest\Parameters` | Hyper-V guest with Integration Services (guest-only keys, never on host) |
| 2 | BIOS registry: `SystemProductName`, `SystemManufacturer`, `BIOSVendor`, etc. containing vmware/virtualbox/qemu/parallels/bhyve/`virtual machine` | Standard VMs with default BIOS strings |
| 3 | MAC OUI (`_mac_oui_definitive`): VMware `000c29/005056`, VBox `080027`, Parallels `001c42`, QEMU `525400`, Xen `00163e` | All major VM platforms (OUIs never appear on real hardware) |
| 4 | Process list: `vmtoolsd`, `vboxservice`, `qemu-ga`, `prl_tools`, `xenservice`, `sbiesvc`, `wdagagent` | Guest tool processes |
| 5 | WMI `wmic` output: `virtual hd` (Hyper-V Gen1), `msft virtual disk` (Hyper-V Gen2/Sandbox), vendor strings | Hyper-V guests, Sandbox via disk caption |
| 6 | **Combined guard**: Hyper-V MAC OUI (`_mac_oui_hyperv`: `000d3a`, `001dd8`, `00155d`) + generic `virtual disk` in WMI — **both required** | Hyper-V guest without IS, custom BIOS |

**Hyper-V host false-positive risk (known issue)**: `00155d` vEthernet adapters appear on physical machines with Hyper-V enabled (Docker/WSL2). The combined guard (Layer 6) can false-positive if the host ALSO has Storage Spaces/iSCSI disks showing "Virtual Disk". Layer 6 is a fallback only; Layers 1–2 already cover standard Hyper-V guests reliably.

## Startup, Auth & Exit/Logout flow

Module import order (all at module level, before `app.mainloop()`): `_ensure_single_instance()` (Windows named mutex `Global\SRT_TTS_Studio_SingleInstance`, stored in `builtins._srt_studio_mutex`) → security checks → app window created **hidden** → `app.after(50, show_splash_then_auth)` → splash (3 s) → `run_auth()` shows the password dialog (`show_set_password_dialog` first-run / `show_login_dialog`) → on success `app.deiconify()`. The **login screen is the auth dialog at startup**; there is no separate post-launch login window.

**Splash screen** (`show_splash_then_auth`, near the end of the file just before `app.mainloop()`): a borderless 320×320 `Toplevel` poster — `logo.png`/`logo.ico` cover-fit via PIL, bottom scrim for text legibility, rounded corners via a magenta `#FF00FF` transparentcolor key (chosen because near-black keys speckle dark pixels in the image), animated rainbow title (`_rainbow_color`), plus startup music (`start_bg_music`). After 3 s `_close_splash()` runs the internet check (`check_internet()` — **hard-exits if offline**), then schedules `_report_startup_diagnostics` (200 ms), `run_auth` (100 ms), and `_session_check_on_startup` (1500 ms). The poster build is wrapped in try/except with an emoji-text fallback, so missing PIL/`ImageTk` (imported guarded) never blocks startup. `splash_preview.png` in the repo root is just a design-preview render, not loaded by the app.

Two ways to leave the running app — both live near the bottom of the file:

| Trigger | Function | Behavior |
|---|---|---|
| Window **X** button (`WM_DELETE_WINDOW`) | `on_app_close()` @24236 | Confirm dialog → `stop_all_processes()` → goodbye sound (`naycaugioi.wav`, sync) → `os._exit(0)`. Quits for good. |
| **Logout** button (`btn_exit`, top-right `_g6`) | `on_logout()` @24263 | Same X effect (confirm + stop processes + goodbye sound), but **relaunches** instead of exiting → returns to the login screen. |

**Logout relaunch must NOT use `os.execl`.** Under PyInstaller onefile, re-exec inherits the bootloader's injected env vars (`_MEIPASS`, `_PYI_*`, `SSL_CERT_FILE`/`SSL_CERT_DIR`) pointing at the temp extraction dir that gets cleaned up on exit → `FileNotFoundError` in `ssl`/`edge_tts` at next import. Instead `on_logout()`:
1. **Releases the single-instance mutex** (`ReleaseMutex` + `CloseHandle` on `builtins._srt_studio_mutex`) — else the fresh process hits "Phần mềm đang chạy!".
2. Spawns a brand-new process via `subprocess.Popen` with a **cleaned env** (those PyInstaller vars stripped so the new bootloader sets them fresh), handling both frozen `.exe` and dev `python` invocation.
3. `os._exit(0)` the current process.

## UI Architecture Patterns (apppp_integrated.py)

### Sidebar-workspace layout (replaced the old flat `_brow*` rows)

The UI was **redesigned** into a sidebar-navigation + paged-workspace layout (~line 5022, `# BO CUC SIDEBAR-WORKSPACE`). The old flat button rows `_brow0`–`_brow8` **no longer exist** — features are now grouped into "pages" reached from a left sidebar. (`_brow*` greps now only match `_browse_*` file-picker callbacks.)

- **Two columns** (~line 1371): `_left_col` (width 232, navy sidebar) holds `ws_nav`; `_right_col` splits via grid into a console area (`_vpane`, row 0) on top and the scrollable function area `ws_content` (row 1) below. `button_frame = ws_content` is kept as a **backward-compat alias** (line 1395) so older code referencing `button_frame` still works.
- **Pages** (`ws_pages`, ~line 5041): one `CTkFrame` per key in `_WS_KEYS = ["dashboard","tts","voice","textaudio","doc","extract","translate","video","editstudio","manga","tools","system"]`. `show_workspace(key)` (~5047) `pack_forget`s all pages and packs the chosen one, and highlights the active sidebar button. Sidebar items + captions come from `_WS_NAV_ITEMS` (~5070). The **default landing page is `"dashboard"`** (the `show_workspace("dashboard")` call right after all sections are built).
- **Sections (cards)** — `_make_section(title, subtitle, accent, ws=KEY, parent=None)` (~5177) creates a titled card and returns its `body` frame. By default it packs **inside `ws_pages[ws]`**; pass `parent=<frame>` to pack it into an arbitrary frame instead (used by the dashboard's collapsible diagnostics zone). Helpers `_sec_row(parent)` (horizontal) / `_sec_col(parent)` (equal-width column, `expand=True`) / `_sec_sublabel(parent, text)` build the layout inside a card. Buttons still pack `side="left", expand=True, fill="x"` for equal width within a row.
- **Console toggle** — `toggle_console()` (~5131) hides/shows the `_vpane` row and reallocates grid weight to the function area.

**To add a new feature button/group:** call `_make_section(..., ws="<page>")` to get a card body (pick the page it belongs to, or add a new key to `_WS_KEYS` + an entry to `_WS_NAV_ITEMS`), then pack widgets into `_sec_row`/`_sec_col` frames within it. **Widget variable names were kept identical across the redesign** — so existing handlers and `set_mode()` did not need changes.

### Dashboard page (`"dashboard"`) — read-only overview + shortcuts

### Webtoon downloader page (`"manga"`) — `_manga_*`

Sidebar page **📚 Tải truyện (Webtoon)** (key `"manga"` in `_WS_KEYS`, nav item inserted into the TIỆN ÍCH group after `editstudio`/`video`). Downloads comics for offline reading via a **site-adapter system**. Built as a single `_make_section(..., ws="manga")` card right before `show_workspace("dashboard")`.

- **Site adapters** (`_manga_get_adapter(url)` matches by netloc): `_MANGA_ADAPTERS` holds per-site configs (`match` domain substrings, `chapter_link_re`, `image_res` list, `backfill` flag, `chap_url(base,i)`); unknown hosts fall back to **`_MANGA_GENERIC`** (best-effort — tries `data-src`/`data-original`/`data-lazy-src`/`data-aload`/`src`, picking the regex that yields the most valid images via `_manga_extract_images`, junk-filtered by `_manga_is_content_img`). **To add a site: copy the truyenqq block in `_MANGA_ADAPTERS`, change `match` + the 2 regexes.** `_manga_extract_chap_num` pulls the chapter number for `chapter-`/`chuong-`/trailing-digits URLs. Built-in adapters: **truyenqq** (`backfill:True`, 100-cap probe) and **hentaivnx** (`match:["hentaivnx"]`, covers both `.com`/`.live`; static render, Cloudflare is CDN-only so plain urllib passes; chapter list on the series page `<a href=".../chapter-N/<id>" data-id="..">`, images sit in `src` on `*.2tcdn.cfd`; `backfill:False` because the chapter URL's trailing numeric ID can't be guessed). **`_manga_worker`'s single-chapter detection** strips the trailing numeric ID for naming (hentaivnx `.../chapter-8/612561` → folder `chapter-8`) while leaving `.../chapter-5`-style URLs unchanged.

URL containing `/chapter-` or `/chuong-` = single-chapter mode. Range box (`manga_chap_var`) accepts `1-10` / `1,2,5` (empty = all). Re-running skips already-downloaded images (resume-safe).
- **Per-chapter retry + connection resilience** (`_manga_worker`, urllib path): `_manga_http` retries 3× with escalating backoff (1.5/3/4.5s) on transient network errors (host forcibly closing the connection — `WinError 10054` / "Remote end closed connection"); previously only image downloads retried, not the chapter-HTML fetch, so one reset lost the whole chapter. A chapter is "failed" if image-list fetch errors, no images, **or missing pages** (`ok < total`); `_grab_chapter()` (closure) does one chapter, failed ones collect in `failed`, then **2 auto-retry passes** run over just the failures (re-running = resume since downloaded pages are skipped). Remaining failures are listed with names+URLs at the end. Whole-series merge re-sorts `done_folders` by chapter order (retried chapters append out of order). **Truncated-image guard**: a connection cut mid-image leaves a partial file that later raises `image file is truncated (N bytes not processed)` during PDF build. `_manga_download_image` now validates every downloaded file with `_manga_image_ok()` (forces `im.load()` with `LOAD_TRUNCATED_IMAGES=False`) and **retries up to 4× on a truncated/incomplete image** (a partial image also makes the chapter "failed" → caught by the retry passes); the resume skip-check also re-verifies existing files so a previously-truncated file gets re-fetched. `_manga_imgs_to_pdf` is also hardened — sets `LOAD_TRUNCATED_IMAGES=True`, `im.load()`s each page, and **skips unreadable images** (logs the count) instead of aborting the whole PDF.

### set_mode() — UI state machine
`set_mode(mode)` is the single function that enables/disables all buttons and controls. It must be called from the main thread (use `app.after(0, lambda: set_mode("..."))` from worker threads). Every new feature needs:
1. Its buttons added to a `_feature_btns` list inside `set_mode`
2. New `elif mode == "feature_ready":` / `"feature_running":` / `"feature_done":` branches
3. The feature's buttons included in the disable sweep of all unrelated modes

Current modes: `srt`, `pdf`, `pdf_tts_done`, `video`, `reset`, `tts_running`, `tts_stopped`, `tts_done`, `scanning`, `scan_done`, `scan_done_clean`, `repairing`, `repair_done`, `cleaning`, `clean_done`, `videocr`, `videocr_running`, `videocr_done`, `video_stt`, `video_stt_running`, `video_stt_done`, `compress_ready`, `compressing`, `compress_done`, `mux_idle`, `mux_ready`, `muxing`, `mux_done`.

### Video OCR pause/stop/resume (process-tree control)

"Tách Sub Cứng (OCR)" runs the external **VideOCR CLI** as a subprocess (`_run_videocr_thread`), which spawns its own worker children — so pause/resume can't go through stdin. ### Thread safety
All UI mutations **must** happen on the main thread. From any worker thread:
```python
app.after(0, lambda: log("message"))
app.after(0, lambda: set_mode("done"))
update_progress(current, total)  # safe — internally uses app.after
```
Never call `log()`, `set_mode()`, or any CTk widget method directly from a thread.

### Progress bar
Always use `update_progress(current, total)` — never manipulate `progress_var` or `progress_bar` directly. The function is thread-safe and drives the animated canvas bar. Parse ffmpeg progress from stderr via `re.search(r"time=(\d+):(\d+):([\d.]+)", line)` and convert to percentage of total duration.

**Windows taskbar progress** (`_taskbar_progress(value)` called inside `_update`, cleared in `_hide_progress_bar`): pure-ctypes COM `ITaskbarList3` (no pip dep; vtable slots 3/9/10 = HrInit/SetProgressValue/SetProgressState — recipe verified on this machine), lazy-init on first update against `GetParent(app.winfo_id())`, any COM failure disables it for the session silently. Main-thread only.

**ETA**: `update_progress` keeps a sliding window of the last 30 `(time.monotonic(), value)` samples (`_ETA_SAMPLES`, main-thread only inside `_update`) → average speed → `progress_bar.eta_text` ("còn ~5p12s"), drawn next to the `%` above the knob. Resets when value drops >0.05 (new/restarted job) or hits 1.0; shown only after ≥3 samples spanning >2s. Any flow using `update_progress` gets ETA for free.

### Logging
`log()` / `log_color()` are thread-safe (they `app.after` to the main thread). Every line is ALSO appended to `logs/session_YYYY-MM-DD.txt` next to `settings.json` via `_file_log()` (called inside `_append_log` and `log_color._do`, i.e. main thread only — no lock needed; lazy-opened handle in `_FILE_LOG`, rotates daily, writes a session header on first open, all failures swallowed). Use this file when debugging a user's "it failed yesterday" report. **`_log_ffmpeg_fail(cmd, rc, note)`** (defined next to the 🎯 scorer block) writes the FULL failing ffmpeg command into the file log as a `[FFMPEG-CMD] rc=… ::` line (list → `subprocess.list2cmdline`; marshalled via `app.after` → `_file_log` so it is worker-thread-safe; all errors swallowed) — hooked at the 4 big failure branches (Nén video, Ghép Audio mux, Audio→Video `_build_one`, `merge_ffmpeg` bat) so a 🐞 support bundle contains the exact command instead of just the stderr tail. The system page has a "📄 Mở log hôm nay" button (`open_today_log`) that opens today's file directly.

**The logbox is a custom canvas widget** (`AnimatedLogBox(tk.Canvas)`, ~line 4159), NOT a CTkTextbox — it draws each log line via `create_text` over an animated background, and exposes a CTkTextbox-compatible shim (`insert`/`delete`/`see`/`tag_config`, `_textbox = self`). It's constructed with `wrap="word"` so long URLs/paths wrap instead of clipping. **Perf trap**: in wrap mode `_render_text` must measure line heights only for the *visible* lines (anchored bottom-up) and cache them in `_wrap_h_cache` (keyed by text, cleared on width change) — the original wrap path measured *every* line (create+bbox+delete) on each render, which made scrolling/heavy logging janky. Any change to wrap rendering must preserve `_wrapped_h`'s lazy + cached measurement.

### Subprocess rules

**Always pre-check executable existence before `Popen`** — on Windows, `Popen` with `CREATE_NO_WINDOW` on a missing executable can hang waiting for Windows Error Reporting instead of raising `FileNotFoundError` immediately:
```python
# Correct pattern (see _check_ffmpeg_exists())
ffmpeg_ok, ffmpeg_path, guide = _check_ffmpeg_exists()
if not ffmpeg_ok:
    for line in guide.splitlines():
        app.after(0, lambda l=line: log(l))
    app.after(0, lambda: set_mode("compress_ready"))
    return
# Only now is it safe to call Popen
proc = subprocess.Popen([ffmpeg_path, ...], creationflags=CREATE_NO_WINDOW)
```

Check pattern: `os.path.isfile(path) or shutil.which(path)`.

**Always use `CREATE_NO_WINDOW`** on all subprocess calls to prevent console windows flashing.

**Never use `communicate()`** for long-running processes — it blocks until completion with no progress. Always use `Popen` + line-by-line `for line in proc.stdout:`.

### Launching external applications
Use `ctypes.windll.shell32.ShellExecuteW(None, "open", exe, args, None, 1)` instead of `subprocess.Popen` to launch GUI apps like Subtitle Edit. This launches them as independent processes (not child processes) so that the Windows IME (Unikey/EVKey Vietnamese input) works correctly. If launched as a child process via `Popen`, UIPI blocks IME keystrokes to the child window.

## Voice Clone Pre-flight Validation Pattern

All TTS entry points that support RVC, VoxCPM, VieNeu, or F5-TTS **must** validate voice clone components **before** calling `set_mode("tts_running")`. If validation fails, log the error and `return` — the UI stays in its pre-run state (no stuck "running" mode).

**Mutual exclusivity:** the six voice paths (Provider online ↔ RVC ↔ VoxCPM ↔ VieNeu ↔ F5-TTS ↔ OmniVoice) are mutually exclusive. `_apply_voice_exclusivity()` disables the other engines' checkboxes/controls whenever one is ticked. Dispatch order in `start_tts()` / the PDF entry: `if VOXCPM_ENABLED → elif VIENEU_ENABLED → elif F5TTS_ENABLED → elif OMNIVOICE_ENABLED → else provider(+optional RVC)`. All five local engines auto-pick device (no manual CPU/GPU UI): RVC resolves `rvc_device_var="auto"` → `cuda:0` if `DETECTED_GPU` else `cpu`; VoxCPM auto-detects in its helper; VieNeu, F5-TTS, and OmniVoice via `--device auto` in their helpers.

### Audio quality check — `_audio_quality_check()` / `_rename_bad_audio()` / `_sanitize_tts_text()`

After every successful MP3 is produced, it's QC'd with **one** `ffmpeg -af volumedetect` call that yields both `mean_volume` and `Duration`. Three failure modes are detected — silence alone is not enough, because Edge TTS hallucination produces audio that is *loud* but far too long:

**`_audio_quality_check(filepath, text="")` → `(is_bad, reason, detail)`**, `reason ∈ {"", "novoice", "toolong", "tooshort"}`:
- **novoice** — `mean_volume < -40 dB` (silent/noise). Normal speech ≈ -12 to -35 dB.
- **toolong** — `dur > 5s` AND `dur > expected*3 + 1.5s` → hallucination / repeat / runaway. (`expected = 0.3 + nchar*0.09`; VN speech ≈ 0.08 s/char measured.)
- **tooshort** — `nchar >= 12` AND `dur < expected*0.30` → truncated / missing content vs subtitle.

Triggers in source text — ellipsis `...` and dialog dashes `- ` — are the common cause of both toolong and tooshort.

**Key runtime fact: Edge TTS is non-deterministic** — the *same* text that produced 35s of garbage in one run produces correct 3.6s audio on retry. So the handling is a **QC + retry loop** (`_QC_MAX_RETRIES = 2`, i.e. 3 attempts) in the provider-TTS flows:

```python
for _qc_attempt in range(_QC_MAX_RETRIES + 1):
    # same text on early attempts (non-determinism fixes it);
    # sanitized text only on the LAST attempt as last resort
    _gen_text = _sanitize_tts_text(text) if _qc_attempt == _QC_MAX_RETRIES else text
    ok = await save_tts(_gen_text, filename)
    if not ok: break
    _bad, _reason, _detail = await run_in_executor(None, _audio_quality_check, filename, text)
    if not _bad: break
    # delete + retry
# if still bad after all attempts → _rename_bad_audio() + FAIL_COUNT += 1
```

**`_sanitize_tts_text(text)`** — used only on the final retry: collapses `...`/`…` → `, ` and strips leading dialog dashes, preserving spoken content. (Don't apply it on attempt 0 — it occasionally trips Edge TTS "No audio received", and plain retry already recovers most cases.)

**`_rename_bad_audio(filepath, idx, reason, detail, label="")`** — renames to `line_0002_novoice.mp3` / `_toolong` / `_tooshort`. Original name no longer exists → next Resume regenerates that line, and the suffix tells the user which lines to inspect.

**Split-recovery for persistent `toolong` — `_tts_recover_toolong()` / `_tts_recovery_split()` / `_tts_recovery_concat()`** (defined right after `_sanitize_tts_text`): when the retry loop exhausts and the final reason is **`toolong`** (hallucination/repeat/runaway — regenerating the SAME text keeps failing), the provider batch loops try a **deterministic** rescue BEFORE `_rename_bad_audio`: `_tts_recovery_split(text)` splits the line at the punctuation boundary nearest the middle (`.!?…` → `,;:` → whitespace; recurses when a half is >160 chars → ≥2 parts, or `[text]` for <20-char lines = no rescue), each part is generated **separately** via `save_tts` (2 attempts each, QC'd individually — a fresh generation of a shorter distinct string usually doesn't hallucinate), then `_tts_recovery_concat()` ffmpeg-concats the QC-clean parts (concat demuxer + libmp3lame re-encode) and the joined file is QC'd once more. Success → logged `🔪 … tách N câu` + counted as a normal `gen` + `_tts_cache_put` (the parts were trimmed by `save_tts` so the join is tight); any failure (a half still bad, concat error, joined file still `toolong`) → falls through to the original rename+FAIL. Wired into the 3 provider batch loops (`generate_tts` seq, `_generate_pdf_tts` seq, the shared parallel worker `_tts_par_one`) in the `elif ok and _bad:` branch. **Only for non-RVC provider flows** (RVC preserves duration so it's never the `toolong` source; the parallel worker is always non-RVC Edge). Verified 2026-07-05: split picks the mid-sentence/comma boundary correctly + ffmpeg concat of 1.0s+1.5s parts = exactly 2.5s.

Applied to all 4 TTS flows, QC'd on the **final** file. Provider flows get the full retry loop; VoxCPM flows get detection + rename only (the helper does its own silence-retry internally, and re-running a single line mid-batch isn't feasible — text is passed via an `idx → text` map built from `items`):

| Flow | QC point | Retry loop? |
|---|---|---|
| `generate_tts()` — SRT + Provider | After `save_tts`, before RVC | ✅ |
| `_generate_pdf_tts()` — PDF + Provider | After `save_tts`, before RVC | ✅ |
| …both, when RVC enabled | Again on RVC **output** | detection + rename only |
| `_run_voxcpm_batch()` — SRT + VoxCPM | After ffmpeg wav→mp3 | detection + rename only |
| `_run_voxcpm_batch_pdf()` — PDF + VoxCPM | After ffmpeg wav→mp3 | detection + rename only |
| `_run_vieneu_batch()` / `_run_vieneu_batch_pdf()` — VieNeu | After ffmpeg wav→mp3 | detection + rename only |
| `_run_f5tts_batch()` / `_run_f5tts_batch_pdf()` — F5-TTS | After ffmpeg wav→mp3 | detection + rename only |

**RVC output is QC'd twice over**: once on the provider-TTS audio feeding into RVC (full retry loop), then again on the RVC output (detection + rename, label `[RVC]`). RVC preserves duration so the second pass mainly catches `novoice` (RVC producing silence without raising).

### TTS text pre-processing — `_apply_glossary()` does BOTH glossary AND number reading

Despite the name, `_apply_glossary(text)` is the single TTS text pre-processing hook (called from `save_tts` + all 16 local-engine texts-json dumps): ① **OCR/dirty-char cleaning** (`_clean_ocr_text`, see below), then ①b **🧹 user regex rules** (`_apply_text_rules` — `text_rules.json` next to settings, edited via `open_text_rules_dialog` "🧹 Luật lọc text" on `voice_profile_row`: lines `pattern => repl`, compiled with `re.M`, bad patterns skipped with a log, 🧪 test button; DELETES/replaces junk the TTS would otherwise speak — translator notes `[TN:…]`, "Đọc tiếp tại…" footers; in `_CFG_BUNDLE_FILES`), then ② glossary substitution, then ③ **teencode normalization** (`_teencode_normalize`, gated by `teencode_var` checkbox "Đọc teencode (ko→không)" on `voice_row1b`, default ON, persisted in ui_prefs: `_TEENCODE_MAP` ~28 chat abbreviations `ko/dc/vs/ntn/mn/…` → full words; matches whole-word **lowercase-only, case-sensitive** so "BT"/"VS Code"/"100k"/"tokyo" are untouched; runs AFTER glossary so user glossary definitions win), then ④ **Vietnamese number normalization** (`_vi_num_normalize`, gated by the `vi_num_var` checkbox "Đọc số tiền/ngày/giờ kiểu Việt" on `voice_row1b`, default ON). `_vi_int_words(n)` converts integers to Vietnamese words (mười lăm / hai mươi mốt / một trăm linh năm / không-trăm-linh rule for inner groups, up to nghìn tỷ). Patterns are deliberately narrow to avoid false positives: money needs a đ/đồng/vnđ/₫ suffix (with `(?!\w)` so "5điểm"/"đô" don't match), dates need full `dd/mm/yyyy` (so "3/4" fractions survive; skips the "ngày " prefix if already present), times are `NhMM`/`Nh` with range checks (24h/19h99 left untouched). **🔢 Roman numerals + units** (same gate): `_VI_ROMAN_RE` turns `Chương/Phần/Tập/Hồi/Quyển/Chapter/Part + UPPERCASE roman` into a digit ("Chương IV"→"Chương 4") — `_roman_to_int` validates by re-encoding so `IIII`/`IC` and ordinary words ("Mới") never convert; `_VI_UNIT_RE`/`_VI_UNIT_MAP` expand measurement units after a digit (`km/h`, `km²`, `km`, `cm`, `mm`, `kg`, `mg`, `ml`, `°C`→"độ xê", `%`→"phần trăm"; longest-first alternation + `(?![\w/%])` so "5kms" is untouched). Any normalization exception falls back to the original text — pre-processing must never block TTS.

### Emotion tags per line — `_emo_parse` / `_EMO_PRESETS` ("[vui] Câu thoại…")

A line may start with an emotion tag from the **hard whitelist** `_EMO_PRESETS` (`[vui] [buồn] [giận] [sợ] [nhanh] [chậm] [thì thầm] [hét]`, diacritic-less aliases in `_EMO_ALIAS`; anything else — `[nhạc]`, long brackets — is real content and untouched). Defined next to `_edge_rate` (~17240). Effects: **Edge TTS** applies rate/pitch deltas ON TOP of the user's `edge_rate/pitch_var` (`_edge_rate_emo`/`_edge_pitch_emo`, clamped ±90/200% and ±90Hz — so casting per-rule overrides still stack); **every other provider/engine just strips the tag** so it's never spoken — `save_tts` parses BEFORE `_apply_glossary` (to capture the tag), and `_apply_glossary` itself strips as its first step (covering the 16 local-engine texts-json dumps; double-parse is harmless since the tag is gone). QC expected-duration uses the tagged text (a ≤12-char tag inflates the estimate ~1s — inside tolerances). Author tags by hand (SRT convention) or bulk-add via 🪄 SRT AI transform or the dedicated **🎭 Tự gắn cảm xúc (AI)** button below. **🎭 Punctuation auto-pace** (`auto_emo_var` checkbox on `voice_row1c`, default OFF, persisted `auto_emo`): when a line has NO explicit tag, `_auto_emo_of(text)` derives one from the ending punctuation — `!` → `nhanh`, `...`/`…` → `chậm` (deliberately ONLY those two mild deltas; closing quotes stripped first). Hooked in `save_tts` right after `_emo_parse` (explicit tags always win); `_tts_cache_key` appends `|ae1` when ON so toggling can't reuse the other mode's cached audio.

**Auto-tag — `srt_ai_emotion()` ("🎭 Tự gắn cảm xúc (AI)", `btn_srt_emo`, SRT page io column)**: one-click pass that sends every line to the translate LLM (`_translate_active_key` — cloud only, Offline refused; batched `_SRT_AI_BATCH` via the `[[n]]` marker protocol + `_parse_marked`) asking it to pick ONE whitelist emotion or `-` (neutral) per line. `_emo_canon(word)` normalizes the LLM's answer through the same `_EMO_ALIAS`/`_EMO_PRESETS` logic as `_emo_parse` (returns the canonical key or None). Writes `<name>_emo.srt` — each tagged line gets `[key] ` prepended after `_emo_parse`-stripping any existing tag (idempotent: re-runs replace old tags, neutral lines drop them) — then reloads (same epilogue as ✂/🪄, incl. the "delete audio of changed lines" askyesno). Shares the `_SRT_AI_RUNNING` lock (translate-button pattern, NOT in `set_mode`). Defined just after `open_srt_ai_transform_dialog`. Effect is strongest with Edge TTS; other engines just strip the tags.

### Per-line voice tag — `[giọng:tên_hồ_sơ]` (`_voice_tag_parse` / `_voice_tag_edge`)

A line may start with `[giọng:tên]` (aliases `[giong:]`/`[voice:]`, `_VOICE_TAG_RE`, defined next to `_emo_parse`) — that line is read with the named **voice profile's** Edge voice + rate + pitch, without touching global state → manual casting of scattered dialogue lines with zero 🎭 Phân vai setup. **Deliberate limits**: honored only when the CURRENT provider is Edge TTS AND the named profile is an Edge provider profile (switching local engines/RVC mid-batch is heavy + racy — that stays 🎭's job); anything else logs a reason ONCE per name (`_VOICE_TAG_WARNED`) and reads with the current voice. `save_tts` parses the voice tag BEFORE `_emo_parse` (tag order: `[giọng:x] [vui] text`; when a voice tag is honored, the profile's rate/pitch are used as-is — emotion deltas are skipped for determinism), overrides the `edge_tts.Communicate` voice/rate/pitch per line, and suppresses 🌐 code-switching for that line. `_apply_glossary` strips the tag as its FIRST step (before emo strip) so all local engines/other providers never speak it. Profile rate/pitch with bad format falls back to the UI's current `_edge_rate()`/`_edge_pitch()`; name lookup is case-insensitive. **Cache interplay**: `_apply_glossary` strips the tag from the preprocessed text, so `_tts_cache_key` appends `|vt:<tên_lower>` when a tag is present — "`[giọng:x] Vâng`" never collides with plain "`Vâng`". Fixture-tested (parse/alias/mid-line-no-match, profile resolve incl. case-insensitive + local-engine refusal + empty-rate fallback, cache-key split). **🗣 Casting-rules export (`_cast_export_voice_tags`, "🗣 Xuất tag [giọng:] vào SRT" button in the 🎭 casting dialog)**: bakes `CASTING_RULES` into `[giọng:profile]` tags per line → `<srt>_cast.srt` + reload — the SRT becomes self-contained (casting survives without the `.cast.json` sidecar, portable to another machine) and runs as a NORMAL batch (cache + parallel Edge) instead of the slow `run_multivoice_batch`. Idempotent (old voice tags stripped first); rate/pitch-only "(Giọng UI)" rules can't be expressed as tags → counted + logged as skipped; non-Edge profiles warned (tag falls back at TTS time). Offers deleting existing per-line audio (generated pre-tag). Fixture-tested (in/out-of-rule lines, rate-only skip, idempotency).

### OCR/dirty-char cleaning + non-speakable skip (`_clean_ocr_text` / `_is_speakable`)

These two helpers (defined just before `_apply_glossary`) fix **deterministic** TTS failures that the QC retry loop can't (retrying the same dirty text fails identically) — the common root cause of `toolong`/`tooshort`/`novoice` on OCR-sourced SRTs:

- **`_clean_ocr_text(text)`** runs as the FIRST step inside `_apply_glossary` (so it applies to every engine + flow, from attempt 0, NOT just the last-resort retry like `_sanitize_tts_text`). It: NFKC-normalizes; drops the OCR replacement char `�` + invisible chars (zero-width/bidi/BOM/soft-hyphen, via the `_OCR_DROP_CHARS` translate table built from `_OCR_DROP_CODEPOINTS`) + control chars (keeps `\t\n\r`); replaces SSML-breaking `< > &` with spaces (Edge TTS builds SSML internally → a bare `<`/`&` truncates output = `tooshort`); and collapses ≥5 identical consecutive non-digit chars to 2 (anti-runaway = `toolong`, digits excluded so `1000000` survives). Never removes speakable content; returns the original on any empty result. This is distinct from `_sanitize_tts_text` (which DOES alter content — strips dialog dashes, `...`→`,` — and stays last-attempt-only).
- **`_is_speakable(text)`** — true iff the text has ≥1 letter/digit (`[^\W_]`, Unicode) **and is not an `[sfx:tên]` tag** (see below — the tag is an insertion directive, so every TTS flow must skip it without FAIL; this one gate covers all provider + local-engine batches and `_scan_missing_lines`). Lines that are pure punctuation/symbols/music-notes (`♪`) would only ever produce silence (`novoice`) + waste retries, so **all batch flows** skip them (log `⏭ … không có nội dung đọc được`, no FAIL): the provider entry points (`generate_tts`/`_generate_pdf_tts` sequential + `_generate_tts_parallel`/`_generate_pdf_tts_parallel` gather) AND the four local-engine `items` builders (`_run_voxcpm/vieneu/f5tts/omnivoice_batch` + their `_pdf` variants — they filter `_is_speakable` out of `items` so the helper never receives a non-speakable line). `_scan_missing_lines` applies the same guard so skipped lines aren't reported as missing-file FAILs.

### Sound-effect tags — `[sfx:tên]` (`_SFX_RE` / `_find_sfx_file`, Doc/PDF pipeline only)

A standalone line `[sfx:mưa]` in a document/novel inserts an audio file instead of being read. Three cooperating pieces (all defined next to `_is_speakable`): ① `_split_text_chunks` pre-splits on sfx-tag LINES so each tag becomes its own chunk (mid-sentence tags are NOT split — they get read as text; recursion handles the surrounding parts); ② `_is_speakable` returns False for tags → every TTS flow ⏭-skips them (no FAIL, no missing-line report); ③ `merge_pdf_audio` builds `sfx_map {chunk_idx: file}` on the main thread (`_find_sfx_file(name)`: `sfx\` under `_CONFIG_DIR` then `_install_dirs()`, case-insensitive base-name match, exts mp3/wav/ogg/m4a/flac; miss = ⚠ log + skip) and `_insert_sfx_files()` in the worker re-encodes each to `_pdf_sfx_NNNN.mp3` **matching the first speech line's sample-rate/channels** (`_probe_first_srch`, shared with `_make_gap_file` — concat `-c copy` needs uniform streams; verified: 44.1k-stereo wav → 24k-mono mp3 concats seamlessly) then inserts into `files`/`file_idxs` at the right position — `_build_m4b` walks the same lists so chapter marks stay correct. Temps cleaned in the merge `finally`. ### Silence trim on provider TTS output (`trim_silence_var`)

Checkbox "Cắt lặng đầu/cuối audio" (`voice_row1b`, default ON). `save_tts` runs `_trim_edge_silence(filename)` (in an executor) after every successful provider generation: ffmpeg `silenceremove` at -45dB keeping 0.15s padding, with the `areverse` ×2 trick to trim the tail (verified: 0.5s-silence-padded file 2.0s → 1.3s). ### SRT lint — `_srt_lint()` / `srt_lint_report()` ("🩺 Khám SRT")

Pre-flight SRT health check (button `btn_srt_lint`, SRT page io column; auto-summary line on every `load_subtitles`). Detects BEFORE generating: reversed timestamps, empty lines, >400-char lines, overlapping start times (guaranteed voice stacking), **runs of ≥3 consecutive identical lines** (whisper STT hallucination; exactly-2 repeats are treated as intentional and left alone — autofix merges the ≥3 runs keeping the first line with `end` extended to the run's end), and slots too narrow for the text — using the same duration formula as QC (`0.3 + nchar*0.09`) and `_DUB_MAX_SPEED` so warnings match real merge behavior (❌ = will overflow even at max speed → fix the SRT; ⚠ = will be auto-stretched). Full report caps at 40 items.

**SRT autofix — `srt_autofix()` ("🔧 Sửa SRT (tự động)", `btn_srt_fix`)**: writes `<name>_fixed.srt` and reloads it. Auto-fixes: re-sorts by start time, repairs reversed end<start (end = start + QC-estimated duration), drops empty lines, nudges duplicate/regressed start times (+0.1s, strictly increasing), splits >400-char lines at the sentence boundary nearest the middle (`_srt_split_point`, each half ≥50 chars, slot divided proportionally by text length). It deliberately does NOT fix slot-overflow lines (text longer than the slot even at 2× — only shortening text helps; the report says so) — that's what AI shorten below is for.

**SRT AI shorten — `srt_ai_shorten()` ("✂ Rút gọn AI (dòng tràn khe)", `btn_srt_ai`, SRT page io column)**: fixes the one class autofix can't — overflow lines. `_srt_overflow_lines(include_warn=False)` finds them with the same QC formula and computes a per-line max-char budget (`(slot×speed − 0.3)/0.09 × 0.9`; speed = `_DUB_MAX_SPEED` normally). When ⚠-narrow lines also exist, an askyesno offers **including them** (`include_warn=True` → budget speed = 1.0×, so NO line gets atempo-stretched at merge — natural-voice dub mode); the worker sends `_SRT_AI_BATCH` (25) lines per call as `[[n]] (tối đa X ký tự) text` to the translate LLM (`_translate_active_key` — cloud only, provider Offline refused with guidance), parses via `_parse_marked`, accepts a rewrite only if non-empty AND strictly shorter than the original, writes `<name>_ai.srt` and reloads it (same epilogue as autofix). Translate-button pattern: self-locked via `_SRT_AI_RUNNING`, NOT in `set_mode`. API failures keep originals (1 retry then skip batch); a post-pass logs line numbers still over budget ("vẫn hơi dài — sẽ bị tăng tốc").

**SRT AI transform — `open_srt_ai_transform_dialog()` ("🪄 Sửa SRT bằng AI (yêu cầu)", `btn_srt_ai_free`, SRT page io column)**: generalization of AI shorten — a free-form prompt textbox ("viết trang trọng hơn", "đổi xưng hô", "bỏ từ tục"…) applied to ALL lines via the translate LLM in `_SRT_AI_BATCH` chunks (`[[n]]` marker protocol, `_parse_marked`); the user request is embedded into the system prompt with rules "keep meaning/language unless asked; unchanged lines returned verbatim". ### Duplicate-line TTS cache (`_TTS_CACHE` / `_tts_cache_key`)

Series/anime SRTs repeat lines ("Vâng", "Cảm ơn"...) constantly. The 3 provider batch paths (sequential SRT, sequential PDF, shared parallel worker `_tts_par_one`) check the cache via `_tts_cache_get(text)` before calling the API: key = sha1 of `provider|voice|edge_rate|edge_pitch|preprocessed-text`; hit → `shutil.copy2` the previously generated file (logs `♻ OK n (dòng trùng...)`), skipping generation, QC and the anti-throttle delay. Entries are stored via `_tts_cache_put(text, filename)` **only after QC passes**, so copies are QC-clean by construction (and post-trim, since trim runs inside `save_tts`). **Disabled when RVC is on** — RVC converts files in-place after QC, so a cached copy would get double-converted. Dead paths are `isfile`-guarded (key includes voice/rate so setting changes never collide). Regen/Quick-TTS paths intentionally bypass the cache (explicit regeneration wants a fresh take).

**Persistent (cross-session) disk cache**: besides the in-RAM `_TTS_CACHE` dict, each entry is also copied to `<_CONFIG_DIR>/tts_cache/<key>.mp3` (`_tts_cache_dir()`, lazy-created), so a **series re-uses repeated lines across EPISODES and across app restarts**, not just within one batch. `_tts_cache_get` checks RAM first, then disk (re-populating RAM on a disk hit). The disk cache is size-bounded by `_TTS_CACHE_MAX_MB` (~2 GB): `_tts_cache_prune()` runs **once** when the dir is first resolved, deleting oldest-by-mtime files down to ~75% of the cap. All cache I/O is wrapped in try/except — a cache failure never blocks TTS.

### Edge TTS parallel generation (`_TTS_PARALLEL_N = 4`)

`generate_tts()` (SRT + provider) branches at the top: **Edge TTS without RVC** runs `_generate_tts_parallel()` — gathers the missing lines, then `asyncio.gather` over `_tts_par_one()` workers gated by a `Semaphore(_TTS_PARALLEL_N)`. Each worker is a faithful copy of the sequential per-line block (same QC + retry + `_sanitize_tts_text` last resort + `_rename_bad_audio` + FAIL-continue); the anti-throttle delay (`delay_min/max_var`) is kept **per slot** (each worker sleeps between its own lines). Pause = workers holding the semaphore sleep (everything drains); Stop = in-flight lines finish, queued workers early-return, then "PROCESS STOPPED". Netdown/quota set flags in the shared `state` dict → the chain aborts and `generate_tts` maps them to the same `tts_stopped` handling as the sequential path. asyncio is single-threaded so `FAIL_COUNT`/`state` need no locks. **All other providers and any RVC run keep the original sequential loop** (paid-API rate limits; RVC subprocess is heavy). `_generate_pdf_tts` has the same branch via `_generate_pdf_tts_parallel()` — the worker `_tts_par_one(..., prefix="pdf_line_", label="[PDF] ")` is shared between SRT and PDF. `current_index` is not advanced in parallel mode (completion resets it to 0; mid-run Stop + Resume relies on the skip-existing scan, which is order-independent).

### Error handling during generation (FAIL + continue)

When a voice clone step fails **during** a batch run (not pre-flight), the convention is to log the error and **continue** to the next line — never stop the whole process:

```python
# RVC failure mid-batch — FAIL + continue
except Exception as _rvc_err:
    log(f"❌ RVC thất bại tại dòng {current_index}: {_rvc_err}")
    log(f"FAIL {current_index}")
    FAIL_COUNT += 1
# (no return, loop continues)

# VoxCPM helper ERROR:{idx}:... signal — FAIL + continue
elif line.startswith("ERROR:"):
    _fail_idx = int(line.split(":", 2)[1])
    log(f"❌ VoxCPM {line}")
    log(f"FAIL {_fail_idx}")
    FAIL_COUNT += 1
    done_count += 1
    update_progress(done_count, len(items))
```

`voxcpm_helper.py` stdout protocol:
| Signal | Meaning |
|---|---|
| `DONE:{idx}` | Line generated — wav ready to convert to mp3 |
| `ERROR:{idx}:{reason}` | Line failed (audio silent after retries) — main app logs FAIL, continues |
| `WARN:{idx}:{reason}` | Silent attempt, retrying |
| `ALL_DONE` | Batch finished |

**Root overlap bug (fixed):** TTS audio (esp. Vietnamese / Edge TTS) is often longer than a subtitle's time slot, so `amix` overlays adjacent lines → "đè giọng / chồng giọng" (voice stacking) + timeline drift.

**Fix — time-stretch to fit the slot:** for each line, `slot = next_sub.start − this.start`; if the real duration (`_probe_duration_sec` via ffprobe) exceeds `slot − _DUB_GAP_MS`, prepend an `atempo` chain (`_atempo_chain`, capped at `_DUB_MAX_SPEED = 2.0×`) before `adelay`. Each line then ends before the next begins → no overlap, start times preserved. Lines that still overflow at max speed (or whose source subtitles already overlap) are collected and logged with their 1-based line numbers so the user can fix the SRT timing/text. `_DUB_MAX_SPEED` / `_DUB_GAP_MS` / `_DUB_CENTER_MAX_S` are module-level constants just above `merge_ffmpeg`.

**Anti-click fades (always on)**: every line's filter chain gets `afade=t=in:st=0:d=0.03` + `afade=t=out:st={post_atempo_dur−0.035}:d=0.03` (fade-out start computed from the probed duration ÷ atempo factor; lines <0.15s skipped) — kills the "click/tạch" artifacts where hard-cut mp3 edges meet in the amix.

**Silence-centering (optional, `merge_center_var` checkbox "Căn giữa khe lặng")**: when a line is much *shorter* than its slot (`target − actual > 0.3s`), its `adelay` start is pushed forward by `min((target−actual)/2, _DUB_CENTER_MAX_S = 0.8s)` so the voice sits centered in the silence gap instead of hugging the slot start. Off by default (exact subtitle-start sync).

**Output format (`merge_format_var` dropdown "Ra:")**: `_MERGE_FORMATS` maps `mp3/wav/m4a/opus` → (`final.<ext>`, codec args) and is substituted into the generated `run_ffmpeg.bat`. Other features that default to `final.mp3` (Mux, Edit Studio "Load Audio File") still work via their file pickers. **🗂 Keep-old-final (`merge_keepold_var` checkbox on `_merge_opt_row3`, persisted `merge_keepold`)**: before merging, an existing `final.<ext>` is renamed to `final_YYYYmmdd_HHMMSS.<ext>` (rename failure just warns + overwrites) — regen a few lines then re-merge and compare takes.

**Loudness normalize (`merge_loudnorm_var` checkbox, row `_merge_opt_row2`)**: appends `,loudnorm=I=-16:TP=-1.5:LRA=11` to the end of the FINAL amix chain in `filter.txt` (same chain — no extra label needed) → final hits -16 LUFS (YouTube standard). Off by default.

**Background music (`merge_bgm_var` path + `merge_bgm_vol_var`, row `_merge_opt_row4` "🎵 Nhạc nền", both in ui_prefs)**: empty path = off. When set, the speech amix gets a `[speech]` label, the bgm file is appended as the LAST input with `-stream_loop -1` (auto-loop), routed through `volume={vol}` (clamped 0.01–1.0, default 0.12) + a 2s `afade=t=out` ending at the last subtitle's end, then `[speech][bgm]amix=inputs=2:duration=first:normalize=0` — `duration=first` cuts the looped bgm exactly when speech ends (verified with real ffmpeg 8.0: output duration == speech duration, bgm looped past its own length). Loudnorm (if on) moves to this final chain. Missing file → ⚠ log + merge proceeds without bgm.

**Per-line volume leveling (`merge_linevol_var` checkbox, row `_merge_opt_row3`)**: multi-voice casting mixes engines with different loudness (character A loud, character B quiet — whole-mix loudnorm can't fix *between-line* spread). When on, the merge loop probes `_probe_mean_volume()` (ffmpeg `volumedetect`) per line and inserts `volume={gain}dB` into that line's filter chain (atempo → volume → afade×2 → adelay), targeting `_LINEVOL_TARGET_DB = -20`, gain clamped ±`_LINEVOL_MAX_GAIN = 12` dB, skipped for un-measurable/suspect files (mean ≥ -5 dB) and gains < 1 dB. Off by default (+1 ffmpeg probe per line). Count goes into `_LAST_MERGE_REPORT["leveled"]`.

**Synced SRT (`_write_synced_srt`)**: after a successful merge, `final_synced.srt` is written to `OUTPUT_DIR` with timestamps matching the REAL audio (start includes the silence-centering shift; duration = probed length ÷ atempo factor — the merge loop now probes every line, not just slotted ones). ## Lip-sync — 👄 Khớp khẩu hình (`start_lipsync()` / `lipsync_helper.py`)

Video page card `_sec_lipsync` ("👄 Khớp khẩu hình (Lip-sync)"): after dubbing, the character's mouth still moves to the ORIGINAL speech — this step re-renders the mouth to match the NEW audio via **Wav2Lip**. Inputs: **Video** (`lipsync_video_var` — a clip with a clear face), **Tiếng mới** (`lipsync_audio_var` — any audio, or a `_dubbed.mp4` from which Wav2Lip auto-extracts the audio), a **Chất lượng** dropdown (`lipsync_quality_var` → `_LIPSYNC_QUALITY`, `nhãn → (max_height, chunk_seconds, nosmooth)`: Nhẹ máy=480px/10s, Cân bằng=640px/15s, Nét hơn=720px/10s+`--nosmooth`). Output `<video>_lipsync.mp4`.

**RAM/disk guard — downscale + chunking (fixed 2026-07-05):** Wav2Lip's upstream `inference.py` reads the **entire** video into a Python list of raw frames (RAM ∝ frame-count × H × W × 3) before it processes anything, and Windows pages that overflow to `pagefile.sys` on C: → the "tràn RAM + nghẽn đĩa" symptom on a 1080p multi-minute dub. Since `inference.py` is a repo file, `lipsync_helper.py` bounds memory around it in the **`region=="full"` path** (`_run_full`): (1) `--max-height` (default 720, 0=off) pre-downscales with ffmpeg `scale=-2:H` — fewer bytes/frame; (2) `--chunk-seconds` (default 30, 0=off) cuts the video into short segments via `-ss/-t` (scale applied in the same cut, `-an`), slices the matching audio window to a 16k-mono wav, runs `_wav2lip_once(seg_vid, seg_out, seg_wav)` per segment (⚠ each segment spawns a fresh `inference.py` → **reloads the Wav2Lip+S3FD models per chunk**, ~5–10 s each — so keep chunks not-too-tiny), then concat-demuxes the segment outputs and **re-maps the original full-quality `--audio`** onto the joined video (`-c:v copy` → re-encode fallback). Peak RAM is bounded by one chunk's frames regardless of total length. Progress is aggregated across chunks via `state["global_total"]/offset/chunk_frames` (monotonic). Short videos (`dur ≤ chunk×1.5`) take the single-pass branch (still downscaled). **The `region!="full"` (multi-face crop) path is single-pass** (crop already shrinks the frame) — chunk only if that later overflows. Both `start_lipsync` (from the dropdown) and the wizard `_autodub_lipsync_step` (which had NO bounds before — ran full 1080p) now pass `--max-height`/`--chunk-seconds`; the wizard falls back to "Cân bằng" (640px/15s). **Preset RAM math**: RAM ≈ H² × chunk_seconds, so *lighter* presets = **shorter** chunks + lower res (the first cut had "Nhanh"=40s which was heavier than "Cân bằng"=30s — inverted; fixed). `max_height` is capped at 720 (1080 dropped — lip-sync pastes a 96px mouth region, so >720 gains nothing but doubles RAM). Verified the ffmpeg cut/scale/concat+audio-remap chain end-to-end with real ffmpeg 8.0.

**GPU VRAM guard (fixed 2026-07-05):** after the system-RAM fix the bottleneck moved to VRAM — on an 8 GB RTX 4060, Wav2Lip's upstream defaults (`wav2lip_batch_size=128`, `face_det_batch_size=16`) fill dedicated VRAM and **spill into "Shared GPU memory"** (system RAM used as VRAM over WDDM — ~100× slower, ETA balloons to hours). `lipsync_helper.py` now passes **`--wav2lip-batch-size` (default 16, was 128)** and **`--face-det-batch-size` (default 4)** to `inference.py`; S3FD face-detection is the main VRAM hog (runs on full-res frames). Small batches that *fit* in VRAM are far faster than large ones that spill. Each chunk is a fresh process so VRAM resets per chunk (no accumulation). Lower these further via the helper args if a smaller GPU still spills.

**Wav2Lip `inference.py` patches (repo edits — re-apply if the repo is recreated, like the rvc_env patches):**
- **RAM (`datagen` line ~247):** `gen = datagen(full_frames.copy(), mel_chunks)` → drop the `.copy()` (`datagen(full_frames, …)`). `datagen`/`face_detect` only READ the frame list (datagen already `.copy()`s each frame individually), so the whole-list `.copy()` just duplicated ~2 GB of decoded frames per chunk for nothing. Deploy machines that DON'T have this patch still stay bounded via chunking; the patch just halves per-chunk frame RAM.
- **Face-not-detected (`face_detect` line ~87):** upstream `raise ValueError('Face not detected!…')` when ANY single frame lacks a face **aborts the whole run** — fatal for real talking-head video (scene cuts / wide shots / face turned away). Patched to **forward-fill the nearest valid detection box** (leading Nones → first valid; mid/trailing → previous valid) and only raise when NO frame has a face. Face-less frames get a plausible box (slightly-off mouth on those few frames) instead of crashing.

**Note the build machine runs Hyper-V/WSL2**, which reserves a large RAM slice before the app starts — a real contributor to the "still 95% RAM" report; advise `%UserProfile%\.wslconfig` `[wsl2] memory=4GB` + closing Chrome/YouTube if it persists.

The helper also does **per-chunk fail-open** in `_run_full`: if a whole chunk still can't be lip-synced (e.g. 15 s with zero faces), it keeps that segment's ORIGINAL (downscaled) video and continues — one bad chunk no longer wastes the whole video; the rest is still lip-synced (final concat re-maps the full audio regardless).

## Mux Audio → Video (`_run_mux_thread`)

"Ghép Audio Final vào Video" (in the "video" page) — pick a video + a final audio track (e.g. `final.mp3` from Merge FFmpeg), adjust per-source volume, then mux into `<video>_dubbed.mp4`. Functions live just after `open_compress_folder` (`load_mux_video` @12268, `_run_mux_thread` @12422, `start_mux_video` @12621); globals `MUX_VIDEO_FILE` / `MUX_AUDIO_FILE` / `MUX_OUTPUT_DIR` next to the `COMPRESS_*` globals.

- **Volume controls** (`mux_video_vol_var` / `mux_audio_vol_var`): `_parse_volume()` accepts `1.0`, `0.5`, `150%`, `0` → ffmpeg `volume=` factor.
- **Keep-original-audio checkbox** (`mux_keep_orig_var`): when checked **and** the video has an audio track, both streams are `amix`-ed (`amix=inputs=2:duration=longest:normalize=0`); otherwise the final audio replaces the original. Falls back to replace-mode with a warning if the video has no audio.
- **Demucs music-separation checkbox (`mux_demucs_var`, default OFF, shown with the ducking box only in keep-orig mode)**: instead of ducking the original (dialog still faintly audible), `_mux_demucs_music()` extracts the video's audio (ffmpeg → stereo 44.1kHz wav, demucs' training sr), runs `audio_enhancer.py --separate --keep music --stereo` in voxcpm_env (drums+bass+other stems summed = clean instrumental, vocals dropped; verified 2026-07-02: speech −25dB max while music intact), then the mux mixes **clean music + dub** with plain `amix` (no sidechain needed — nothing to duck). The demucs proc is stored in `_VIDEOTOOL_PROC` so ⏹ Dừng kills it; PCT lines drive the progress bar. **Fail-open**: any failure (no voxcpm_env, helper missing, htdemucs model not cached, ffmpeg extract error) logs a ⚠ and falls back to the normal keep-orig+ducking path — mux never dies because of this option. Temp dir cleaned in `finally`. Persisted in ui_prefs (`mux_demucs`); the auto-dub wizard inherits it since it shares the `mux_*` vars. `audio_enhancer.py` gained `--keep vocals|music` + `--stereo` args (defaults unchanged — the 4 ref-audio enhance callers are untouched; music mode skips the 0.95 peak-normalize boost and only attenuates if clipping).
- **Ducking checkbox** (`mux_duck_var`, default ON): only applies in keep-original mode. The original audio is auto-lowered while the dubbed voice speaks and restored during music/SFX-only gaps, via `sidechaincompress` keyed by the dub (`[a1]asplit` → original `sidechaincompress=threshold=0.015:ratio=12:attack=20:release=350` → `amix` with the un-keyed dub). Without it the equal-volume `amix` lets the (often louder) original drown the TTS voice. The auto-dub wizard inherits this default since it shares `mux_*` vars.
- ffmpeg uses `-c:v copy` (no video re-encode → fast) + AAC 192k audio; progress parsed from `time=` like the compress flow.
- **Burn-in subtitles (`MUX_BURN_SRT` module global)**: when set to an existing `.srt` (only the auto-dubbing wizard sets it, via its "Gắn phụ đề cứng" checkbox; cleared in a `finally`), `_run_mux_thread` prepends `[0:v]subtitles='…'[vout]` to the **same** `filter_complex` (ffmpeg forbids mixing `-vf` with `-filter_complex`) and re-encodes the video (filters force re-encode — can't `-c:v copy`). Burn style is user-tunable via `_burn_sub_style()` → `:force_style='FontSize=..,PrimaryColour=..,Outline=2'` (ASS `&HAABBGGRR` BGR colors; syntax verified with ffmpeg 8.0): two wizard dropdowns "Cỡ/Màu" (`mux_substyle_size_var` Nhỏ/Vừa/To → 18/24/32, `mux_substyle_color_var` Trắng/Vàng/Xanh lá; persisted in ui_prefs). The encoder is **GPU-aware**: when `DETECTED_GPU` is set it uses `h264_nvenc -preset p5 -rc vbr -cq 23 -b:v 0` (offloads to the NVIDIA GPU so CPU isn't pinned at 100% — the burn-in step was the cause of a 99% CPU report), falling back to `libx264 -crf 20 -preset veryfast` only when no NVIDIA GPU is detected. **On the GPU burn-in path the source video is also decoded with `-hwaccel auto`** (NVDEC) — offloads video decode off the CPU (libass subtitle rendering still runs on CPU); `auto` falls back to software decode if init fails. Only added when burning (re-encode) + `DETECTED_GPU`; the `-c:v copy` no-burn path needs no decode. Verified `-hwaccel auto` + subtitles + `h264_nvenc` on the RTX 4060. Path escaping via `_ff_sub_filterpath()` (backslash→`/`, `:`→`\:`, `'`→`\'`, wrapped in single quotes).
- Modes: `mux_idle` (only video or only audio picked) → `mux_ready` (both picked, run enabled) → `muxing` → `mux_done`. `_mux_ready_mode()` returns `mux_ready`/`mux_idle` based on which files are loaded. Mutually exclusive with the compress flow (each disables the other's buttons while busy). Completion uses the standard `show_fireworks` + `open_mux_folder`, identical to TTS/compress.

## Edit Studio (`open_edit_studio`)

A Toplevel preview/verify window (`open_edit_studio` ~20535) that plays video frames (ffmpeg raw-frame pipe → PIL → Canvas) with MCI audio as the master clock. State lives in the `es` dict; all playback runs through the audio thread (`_audio_loop`) + `seek_to()`.

Toolbar load buttons: **Load SRT**, **Load Video**, **Load Audio Folder** (per-line `line_*.mp3`, timeline-placed), **Load Audio File**, **Load nhiều Audio** (sequential playlist).

**Load Audio File** (`_load_audio_file`) loads a single full-length track — typically `final.mp3` after Merge FFmpeg (file dialog defaults to `OUTPUT_DIR/final.mp3`). It builds a temp WAV (waveaudio = MCI master clock), sets `es['audio_wav']`/`wav_ready`, then `seek_to(0)`:
- **With video loaded** → **keeps the original video audio** and `amix`-es the loaded track on top (`[0:a][1:a]amix=inputs=2:duration=longest:normalize=0`, video + dub → one master WAV), so you hear original music/SFX *and* the dub. Falls back to dub-only if the video has no audio track.
- **No video** → audio-only mode: `_seek_audio_only()` plays the track as master; clicking a subtitle row seeks to its timecode; `_toggle_play` (Play/Pause) and the ticker's end-of-track reset both branch on `not es['video_path'] and es['audio_wav']`. Temp WAV is tracked in `es['_tmp_wav']` and removed in `_on_close`.

**Load nhiều Audio** (`_load_audio_seq`) — sequential **playlist**, NOT concatenation and NOT timeline: pick many files, they play **one after another** (each file finishes → next starts immediately). Files are natural-sorted by name (`line_0000`, `line_0001`, …). Implemented in the MCI audio thread via a dedicated alias `_ALIAS_SEQ` + handlers `_h_seq_play/pause/resume/stop` (queue ops `seq_play/seq_pause/seq_resume/seq_stop`). **Auto-advance**: the `_audio_loop` poll watches `_mci_mode(_ALIAS_SEQ)` — once it has seen `playing`, a transition to `stopped` triggers `_h_seq_play(idx+1)` (runs on the audio thread → MCI-safe). State: `seq_files`/`seq_idx`/`seq_active`/`_seq_mode`. The ticker updates the current-file status and resets Play when the list ends. `_toggle_play` has a `_seq_mode` branch (pause/resume; restart from 0 if finished). Other loaders call `_exit_seq_mode()` to leave playlist mode. No temp files (nothing is merged). **List UI**: the side Audio tab shows the playlist — `_build_audio()` branches to `_build_seq_list()` when `_seq_mode`, rendering one row per file (name + ▶) into `_aud_rows`; ▶/row-click → `_seq_play_from(idx)` (play sequentially from that file). The ticker highlights the currently-playing row via `_hl_audio(seq_idx)`.

## SRT / PDF Translation to Vietnamese (LLM)

The "translate" page — translate SRT / PDF / **Word `.docx` / `.txt`** to natural Vietnamese via Claude / Gemini / OpenAI / Offline. Three buttons (`btn_translate_srt` / `btn_translate_pdf` / `btn_translate_doc`), toggled together by `_set_translate_buttons()`. **Decoupled from `set_mode()`**: always enabled (no entry in any disable sweep) and self-lock only during their own run (re-enabled in `finally`). They operate on a freshly file-dialog-picked file, NOT `subtitles_cache`/`PDF_CHUNKS`, so they never conflict with a running TTS job.

| Piece | Detail |

**Target language (`translate_target_var` dropdown "Sang:", default "Tiếng Việt")**: `_TRANSLATE_TARGETS` maps 9 labels → prompt descriptions; `_translate_system_prompt` switches between the VN-specialized prompt (xưng hô rules) and a generic native-style prompt for other targets, and the [[n]]-format instruction names the target. **Speaker diarization — deliberately NOT built** (decision 2026-07): acoustic diarization (pyannote) needs a gated HF model + token, a heavy new dep in voxcpm_env, and real-audio quality testing that can't be done blind; the LLM-based "🤖 Tự phân vai (AI)" already covers the casting-assignment use case from text. Revisit only if real users report the AI autocast misassigns speakers too often.

**🈶 Glossary auto-learn (`_glossary_learn_from_pairs` / `_glossary_learn_offer`, defined just above `translate_srt`)**: after a successful (non-stopped) `translate_srt`, capitalized Latin tokens appearing ≥3× in the SOURCES **and** ≥3× in the TRANSLATIONS (the kept-in-translation requirement is the real filter — common English words don't survive into Vietnamese output; `_GLEARN_COMMON` is just a backstop), not already in GLOSSARY, become candidates (cap 15). An askyesno (main thread, `app.after(600)`) offers adding them with **reading = the term itself** (identity — an empty reading would be dropped by the 📖 dialog's save; identity is a TTS no-op) then `_glossary_compile()` + `_glossary_save()`. Effect: recurring character names stay consistent across episodes (glossary terms are injected into the translate prompt) with zero manual glossary work. SRT flow only — the unattended novel/doc paths deliberately don't prompt. Fixture-tested (kept-name detection, The-filter, already-in-glossary skip, <3-occurrence skip).

**🔗 Bilingual merge/split (`merge_bilingual_srt` / `split_bilingual_srt`, row `_g4_biling_row` under 🪞)**: merge = pick source SRT (auto-guesses `_vi.srt` beside it) → `<src>_bilingual.srt` with `gốc
dịch` per cue, timestamps from the source (count mismatch → askyesno, pairs by order, surplus keeps one language; identical/empty translation lines aren't duplicated). Split = the inverse for any 2-line-per-cue file → `_line1.srt` + `_line2.srt` (single-line cues copy the same text into both so no content is lost — the split files are what TTS reads cleanly). Instant main-thread, no lock; fixture-tested roundtrip. **🎧 Audio song ngữ học tiếng (`bilingual_learning_audio`, `btn_biling_audio` — 3rd button on `_g4_biling_row`)**: picks a bilingual SRT → small dialog (dropdown giọng câu GỐC listing ONLY Edge-provider profiles — the `[giọng:]` tag honors nothing else; order Gốc→Dịch / Dịch→Gốc; checkbox đọc lại câu gốc lần 2) → builds the alternating chunk list (1 câu = 1 chunk, deliberately NOT through `_split_text_chunks` — the interleave must survive; profile chosen → `[giọng:tên] ` prepended to each original line) into `PDF_CHUNKS` + `set_mode("pdf")` + jump to the doc page — user runs Đọc (TTS) + Merge with `pdf_gap_var` ~800–1200ms for the recall pause. No profile → log hints to enable 🌐 code-switching. Fixture-tested (Edge-only dropdown filter, default interleave, profile+reverse+repeat sequence).

**Bilingual mode** (`translate_bilingual_var` checkbox): SRT line becomes `original\ntranslated`; PDF writes both. **Context field** (`translate_context_var`) feeds the system prompt for consistent pronouns/xưng hô — the single biggest quality lever for VN subtitles (online providers only).

**Translate→TTS chaining** (`translate_then_tts_var` checkbox "Dịch xong đọc luôn (SRT)"): on successful (non-stopped) `translate_srt()`, `_chain_translate_to_tts(out_path)` runs on the main thread — sets `SRT_FILE` to the `_vi.srt`, resets `current_index`, `load_subtitles(force_select=False)`, `set_mode("srt")`, then `start_tts()`. Warns (but proceeds) if bilingual is on, since TTS would read both languages.

### Pause / Resume / Stop (translate controls)

Three controls (`btn_tr_pause`/`btn_tr_resume`/`btn_tr_stop`) drive module flags `TRANSLATE_PAUSED` / `TRANSLATE_STOP` (enabled only while a translate job runs, toggled via `_translate_set_controls`). **Online**: `_translate_segments` checks the flags between each 40-line batch (waits while paused, breaks on stop). **Offline**: the flags can't reach the running subprocess, so the controls also send `PAUSE`/`RESUME`/`STOP` lines to `translate_helper.py` via its **stdin** (`_translate_send_proc`, using the stored `_TRANSLATE_PROC`); the helper runs a daemon stdin-reader thread (`_CTRL`) and checks it between batches. On stop, **partial output is still saved** — untranslated tail keeps the source text (both the helper and the online path back-fill `None`/missing with the original), so the file stays valid. Stop → no fireworks but still reveals the file; normal finish → fireworks + reveal. Progress shows in both the bar and the logbox (`_make_translate_progress_cb`, throttled to 10% steps); on finish the output folder opens via `_reveal_output` (`explorer /select,`).

### Offline (local) translation — provider `"Offline"`

The Row-8 dropdown has a 4th option **`Offline`** that translates fully on-device via `translate_helper.py` (no API/network). `_translate_segments()` dispatches: `TRANSLATE_PROVIDER == "Offline"` → `_translate_segments_local()`, else the LLM path. Local mode ignores the context field (NLLB/envit5 take no instructions).

- **Model**: any HuggingFace seq2seq dir (or HF id) set in ⚙ Cài đặt → `local_translate_model_dir`. Helper auto-detects: `nllb`/`m2m` → `forced_bos_token_id` for `--tgt-lang vie_Latn`; `envit5` → `en: ` prefix, EN→VI only; else generic `generate()`. Recommended: `facebook/nllb-200-distilled-600M` (multilingual) or `VietAI/envit5-translation` (EN→VI, best VN style).
- **Source language** (`local_translate_src_lang`, NLLB only) is a friendly dropdown in settings mapping to codes (`eng_Latn`, `zho_Hans`, `jpn_Jpan`, …); envit5 ignores it. The first option **`Tự động phát hiện` (code `auto`)** lets `translate_helper.py` detect the source language from the segment text (`_detect_nllb_lang`): it tries **`langdetect`** first (distinguishes Latin-script langs EN/FR/ES/DE/… — install it into the translate env, `pip install langdetect`; helper degrades gracefully if absent), then a dependency-free **script heuristic** (Han/kana/Hangul/Thai/Cyrillic → zho/jpn/kor/tha/rus; Latin → defaults to `eng_Latn`). On detect the helper prints `AUTODETECT:<code>` which the app logs as `🔎 Tự động nhận diện…`. Only affects NLLB (envit5 is always EN→VI).
- **Env**: `_translate_segments_local()` picks the interpreter in this order: `TRANSLATE_ENV_OVERRIDE` (settings `translate_env_override`, an explicit `python.exe`) → `_find_voxcpm_python()`. Needs `torch`+`transformers`+`sentencepiece`. `translate_helper.py` is one of the **15 companion scripts** (added to all 3 onefile spec `datas`, build_all.bat step-0 validation + both copy loops, step-6G fail-closed copy).
- **Tokenizer-version gotcha**: `voxcpm_env` ships `transformers 5.x`/`tokenizers 0.22.x`, which **loads NLLB/Marian fine but FAILS on envit5** (T5/unigram SentencePiece) with `argument 'vocab': 'dict' object cannot be converted to 'Sequence'`. To use envit5, point `translate_env_override` at a **separate venv** with older pins (`transformers==4.41.2` + matching `tokenizers` + `sentencepiece` + CPU `torch`). The helper catches model-load failures → prints `LOAD_ERR:` (exit 3) so the app shows a clear message instead of "mã 1".

### Relative auto-detect (added) — copy beside the exe, no Settings needed

Resolution order for the 3 big external folders is now: **settings.json → relative auto-detect beside the exe → hardcoded `E:\`/`C:\Users\os\` default**. Two module-level helpers drive this (defined just above the `VIDEOCR_CLI_DIR` global):

- `_install_dirs()` — returns the exe dir (frozen) / script dir plus up to 3 parent levels, as the search roots.
- `_auto_find_dir(*subpaths)` — returns the first existing subdir under any install root (`""` if none).

Wired in at three points so dropping the folders next to the `.exe` "just works":
| Dep | Auto-detected subpaths (beside exe / parents) | Fallback |
|---|---|---|
| `VIDEOCR_CLI_DIR` | `VideOCR\CLI`, `VideOCR-CLI`, `VideOCR-1.5.1\VideOCR-1.5.1\CLI` | hardcoded `C:\Users\os\...` |
| VoxCPM model (`voxcpm_ckpt_var` default) | `VoxCPM\pretrained\VoxCPM-1.5-VN`, `VoxCPM-1.5-VN`, `VoxCPM-model` | hardcoded `E:\VoxCPM-1.5-VN\...` |
| `voxcpm_env` python (`_find_voxcpm_python`) | walks up from ckpt **then** `voxcpm_env\Scripts\python.exe` under each `_install_dirs()` root | `None` |

`_run_startup_diagnostics()` calls `_find_voxcpm_python(ckpt)` unconditionally now (even with no model dir) so a beside-exe `voxcpm_env` shows ✅.

Default paths hardcoded in source (final fallback; override via ⚙ Cài đặt):
- `VIDEOCR_CLI_DIR`: `C:\Users\os\Downloads\Compressed\VideOCR-1.5.1\...\CLI`
- VoxCPM ckpt seed: `E:\VoxCPM-1.5-VN\VoxCPM\pretrained\VoxCPM-1.5-VN`
